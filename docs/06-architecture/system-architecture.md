# Системная архитектура

## Назначение

Документ задаёт границы программных компонентов. Он обязателен для агентов до создания кода.

## Контейнеры первого этапа

```text
Unity client -> backend-api -> PostgreSQL
                     |
                     +-> game-server-1
                     +-> game-server-2
```

- `backend-api` — один ASP.NET Core образ с логически изолированными модулями Identity, Profiles, Matchmaking, Match Sessions, Allocation и Observability.
- `game-server-*` — Linux headless Unity + FishNet, один активный матч на экземпляр.
- PostgreSQL — единственное хранилище постоянных данных.

## Владение данными

- Backend владеет аккаунтом, профилем, инвентарём, прогрессом, очередью, результатом матча и наградами.
- Match-server владеет только живым состоянием своего матча. После завершения передаёт проверенный результат backend.
- Клиент не владеет авторитетными данными и не начисляет награды.

## Неподвижные правила

- Код не создаёт карты, модели, анимации, VFX, звук и финальный UI.
- Не создавать новые сервисы до подтверждённой необходимости: сначала модуль в `backend-api`.
- Не давать public API доступ к Docker Engine. На текущем этапе серверы предзапущены, allocator выбирает свободный здоровый слот.
- Изменение межсервисного контракта требует версии, теста совместимости и обновления `service-contracts.md`.
