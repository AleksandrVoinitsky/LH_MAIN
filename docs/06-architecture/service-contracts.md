# Контракты сервисов

## Внешний API

Клиент вызывает backend только через версионированный HTTPS API. Источник истины после реализации — OpenAPI-спецификация, публикуемая вместе с backend.

## Минимальный поток

1. `POST /v1/auth/dev-login` принимает логин и пароль, возвращает короткоживущий JWT.
2. `GET /v1/profile` возвращает профиль по JWT.
3. `POST /v1/matchmaking/queue` добавляет игрока в очередь.
4. `GET /v1/matchmaking/status` возвращает статус ожидания или назначение.
5. Назначение содержит `matchId`, сетевой адрес и короткоживущий match ticket.

## Внутренний контракт

Game-server перед стартом допуска игрока проверяет ticket у backend. Проверка одноразовая, привязана к `playerId`, `matchId`, сроку действия и серверу назначения. Backend принимает результат матча только от аутентифицированного game-server, принадлежащего указанному `matchId`.

## Правила

- Не передавать пароль, JWT или ticket в логи.
- Все команды, меняющие профиль, очередь или награды, идемпотентны и имеют correlation ID.
- Контракты используют transport DTO без Unity API и без `Vector3`, `MonoBehaviour`, `ScriptableObject`.
