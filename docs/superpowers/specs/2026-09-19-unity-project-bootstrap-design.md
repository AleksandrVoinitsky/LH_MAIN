# Подготовка стартового Unity-проекта

## Цель

Подготовить чистую, воспроизводимую стартовую точку для разработки игры на Unity с FishNet: привести структуру проекта к стандартной, настроить Git, сохранить суть существующей игровой документации в Markdown и опубликовать первый коммит в `AleksandrVoinitsky/LH_MAIN`.

## Результат первого этапа

- Корень репозитория содержит стандартные каталоги Unity: `Assets/`, `Packages/` и `ProjectSettings/`.
- Git отслеживает только исходный код, настройки, пакеты и документацию, нужные для воспроизведения проекта.
- `docs/` содержит краткую структурированную документацию проекта в Markdown и индекс навигации.
- Исходный архив с PDF, DOCX и XLSX не входит в репозиторий.
- Удалённый репозиторий GitHub настроен как `origin`; стартовый коммит опубликован.

## Структура репозитория

```text
/
  Assets/
  Packages/
  ProjectSettings/
  docs/
    README.md
    00-overview.md
    01-gameplay/
    02-content/
    03-progression-economy/
    04-ui-social/
    05-technical/
    superpowers/specs/
  .gitignore
  README.md
```

Содержимое существующей папки `My project/` переносится в корень рабочего каталога. Временные и генерируемые файлы Unity и IDE не отслеживаются.

## Git и игнорирование файлов

`.gitignore` исключает как минимум:

- Unity-кэши и временные каталоги: `Library/`, `Temp/`, `Logs/`, `UserSettings/`;
- артефакты IDE и компиляции: `.vs/`, `obj/`, `bin/`, `*.csproj`, `*.sln`, `*.user`;
- архив исходной документации и временную папку его извлечения.

В коммит входят `Assets/`, `Packages/`, `ProjectSettings/`, документация, `.gitignore` и корневой `README.md`.

## Документация

Исходные материалы извлекаются только для анализа. Их содержание консолидируется: повторяющиеся сведения объединяются, второстепенные детали сокращаются, а неоднозначности и противоречия явно отмечаются как открытые вопросы.

Каждый тематический документ отвечает на вопросы:

1. Какова цель системы?
2. Какие ключевые правила и сущности она задаёт?
3. От каких систем она зависит?
4. Что остаётся неопределённым или требует решения?

`docs/README.md` служит индексом. Корневой `README.md` даёт быстрый старт для разработчика и ссылку на документацию.

## Диагностика ошибок CS0579

После публикации стартового коммита проводится отдельная диагностика пяти ошибок Unity Console. Указанная пользователем гипотеза о дублирующихся генерируемых атрибутах LiteNetLib рассматривается как исходная, но не как подтверждённая причина.

Порядок работы:

1. Зафиксировать полный текст всех пяти ошибок и связанные пути файлов.
2. Проверить, не участвуют ли в компиляции локальные сгенерированные артефакты `obj/`, `bin/`, `.csproj` или `AssemblyInfo.cs`.
3. Удалить только безопасно пересоздаваемые неотслеживаемые артефакты и перегенерировать проект Unity.
4. Если ошибка сохраняется, найти и устранить конкретный дублирующий источник в конфигурации или исходниках.
5. Проверить отсутствие ошибок после перезапуска/пересборки Unity и оформить исправление отдельным коммитом.

## Проверка готовности

Перед завершением стартового этапа проверить:

- `git status` не содержит непредусмотренных файлов;
- `.gitignore` исключает Unity-кэши, IDE-артефакты и архив;
- обязательные Unity-каталоги и Markdown-навигация присутствуют;
- `origin` указывает на заданный URL;
- первый коммит опубликован в удалённой ветке.

## Вне рамок этапа

- Реализация игровых механик.
- Изменение версий Unity, FishNet или зависимостей без необходимости для исправления подтверждённой ошибки.
- Хранение исходных PDF/DOCX/XLSX в Git.
